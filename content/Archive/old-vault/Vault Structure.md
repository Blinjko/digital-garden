
## Top Level Folders
There are 4 different top level folders
- Notes - This is where all the notes are
- Archive - A folder that is essentially a trash can, contains old irrelevant notes
- Templates - This is where the obsidian templates will go
- Attachments - This is where all file attachments will be held so that they don't clutter the Notes folder. This is files like, PDF, images, Audio, etc.

Essentially it is a flat style where all the real notes is in the Notes folder.

## Types of Notes
This will help later when we get to style guide for notes. I struggled with this initially because I was trying to make everything Evergreen notes, but I realized this is not a solution.

- Reference Information - these notes are pure technical information. There really is no thought here so it doesn't fit into Evergreen notes, but technical notes are necessary for me and useful. I will make them atomic as possible because I think that format just tends well in general, however over fragmenting information can be harmful. These notes are also not bound to the Evergreen Note Rules. Examples of these kinds of notes are
	- Lecture notes - which are decomposed in a nice manner
	- Notes from textbook / class readings (I'm an engineer so this is mostly technical and not subjective)
	- References on how-to-do somethings. Sort of logs of how I did certain specific tasks in the past. Once again there is no thought here, there is simply a way to do it no more no less.
- Evergreen Notes - these are notes on thoughts and ideas I have had. They will be atomic in concept and linked heavily. I extend this to include personal reflections as well, and these are not just limited to technical ideas, they will encompass all my thoughts.

Technical notes I think are unavoidable in general, and I think they don't really fit into the evergreen structure because there is no *thought*. At school I am fed technical information directly, there is nothing to really think about when noting down formulas and whatnot. On the other hand I can think about the topics and concepts and make evergreen notes on them, but this is not a way that works to log technical information so I had to make a distinction between the two. I also need the technical information I am fed for reference to do work. Work and projects are born out of creative ideas and thoughts, but to actually *do* things I need technical knowledge and info, most of which I will likely not remember, hence why I take notes. A mentioned before, technical notes will be made as atomic as possible and they will be linked topically and conceptually, I think there is much to gain from these efforts despite the notes not being evergreen.

## Tags
Notes will be tagged so that navigation and grouping is easier. I will have to lay down some constraints on tags so that I can avoid tag explosion. 

There will be different types of tags.
- Time tags - these will be tested tags so that I sort notes by dates. The order will be descending time, ex "YYYY/MM/WW" where the week is relevant to the month.
- Note Type Tags - a tag that distinguishes Reference notes from evergreen notes, and maybe some will be added if I find more note types that don't really fit into the outline above.
- Evergreen note types - tags to loosely outline the evergreen note content. E.X, "projects", "thoughts", "reflections", and similar things. More will come along as I do more things, but as time goes on less and less will probably be created.

I do not think I will be using tags to mark topics or domains as I think this could easily get out of hand and become cumbersome, which is precisely what I would like to avoid.

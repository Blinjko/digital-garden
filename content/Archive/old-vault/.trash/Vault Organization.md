Seeing as I will be hosting this on the web using quartz, and moving forward I will likely be using this content I think it makes sense to setup some clear guidelines of how to organize the information inside this vault, and the process of adding new information.

## Thoughts on Note Structure
I agree with the idea that notes should be atomic and heavily linked together. I think this generally makes writing them easier for me but I have found so far that linking can be a bit of extra work when writing, but maybe that is something I should worry about after? 

Nonetheless here is a list of how I want my notes to be
- Atomic - Attempt to fragment the information into discrete pieces keeping information that should be together together. If something is large enough, split it off into it's own note and link to it.
- Linked


## Tools For Organization
Here are the tools at my disposal
- Folders
- Tags
- Notes

### Folders
I can use folders to organize the notes that I have in a structured manner. 

- I think it would be best to keep the amount of top level folders to a minimum, and attempt to not make folder depth's greater than 2
- Folders make it easier to navigate and filter through notes on the website. It also gives a clear look on the UI
- If I use folders to describe the "state" of a note I can easily move them around folders, which is generally less work than re-tagging the note, especially if there are many notes being moved.
- Folders can help with implicitly describing the relevancy of a note which can be useful for finding resources later.
- Quartz also creates custom pages indexing all the files in a folder, which is useful.

### Tags
I think tags can also be easily used to help organize notes, and give general ideas about notes without reading them (I.E reading the tags can give you some surface level info about the note itself).
- Quartz generates index pages for tags, which hold all the notes with those tags. This is very useful since I can easily see all the notes with "x" tag. Apparently these index pages can be nested with the tags to add extra levels of indexing.
- With tags I don't have to make folders, and if I feel like it I can just add tags that I feel are relevant. This helps keep everything in a flat like structure with little to no folders (which is good because it can limit the amount of thought put into organizing).
- A downside of using just tags and little to no folders is that the site is very flat and it just leaves the users to swim and navigate through the files somehow. This generally makes information harder to find.
- Another nice part about tags is that quartz shows them on the graph view, something that it doesn't do with folders.
### Notes / Index Pages
Having a folder structure can make it a bit easier to see how things are organized since I can just expose the folders and their contents. Tags on the other hand lack this intrinsic structure so, unless you know the tags it can be hard to find the notes. A solution to this is to use index pages that users can easily get to and use to navigate the structure in an efficient and easy manner.

## The Organization Plan
Okay, after a bit of thinking and bouncing ideas of ChatGPT, I think I've finally decided that I will use a hybrid system that mainly relies on tags and links. Links are simple, they give relations between each note as they arise, it doesn't take much cognitive effort to create them plus the graph and back links are auto generated.

So, what I think is best is to have 2 top level folders
- Notes
- Archive
Notes serves as a flat file for all the notes essentially. All the notes in here will be linked and tagged as I see fit. Of course nothing is perfect so tags and links will probably evolve with time.

Archive is essentially like my pseudo trash can. Rather than delete, I will put old things there so they aren't in my main notes.

As I said before, tags will be the main way to navigate notes. Luckily quartz generates a tag index automatically and we can nest tags. Tags are easy to change and items can have many tags so hopefully it doesn't involve too much though.

So, essentially reading tags should give you an idea about the note, and I think it would be useful to state the different kinds of tags.

- Domain tags - what domain does this note belong to?
- Status tags - is this note in progress or finished?
- Temporal tags - tags with the year / month or some time
- Project tags - used to distinguish between projects
- Topic tags - used to denote what topics are presented in the note.


## Note Writing Guide
What I hope to create here is simple guidelines on the the note writing process so that it isn't so overwhelming and difficult.

First I think it is important to establish when I will write a note.
- I have class notes to transcribe (from lecture).
- I have thoughts I just want to put down.
- I have a process / something I want to keep for reference later
- Reports on projects / status updates / reflections
- though processes
- etc
That helps illustrate that before writing a note I have some form of information that I just want to log. However to make an effective note I need to not only write the information, I also need to link it, tag it, and fragment it into pieces if necessary. I think doing this all at once can be overwhelming so I think it makes sense to do it one piece at a time. 

So, here is the order in which I think things should be done.
1. Create and title your note, this can always change later so no worries.
2. Immediately tag the note with "seed"
3. Forget about tagging, linking, and whatever else, try to write down the information you want to get down, worrying about everything else later.
4. After the information is down, or you have nothing left to currently add begin re-reading, linking, and tagging the notes.
